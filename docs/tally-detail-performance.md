# 集計画面の明細遅延取得（2026-10-29）

## 動作

運営管理の最初の表示は順位・スコア・サマリーだけとし、「投票明細・感想を開く」で明細を50件ずつ取得する。集計年度・集計元・分母の変更や再集計時には明細を閉じ、新しい集計に対応する明細だけを取得する。取得失敗には再試行ボタンを用意する。

保存済み集計を読む際は、PostgRESTのJSONフィールド指定でサマリーだけをDBから返す。明細はJSON配列の添字を50件分指定して取得するため、ブラウザーだけでなくDBからアプリへの全明細転送も避ける。空ページと最後の50件未満のページを含め、固定された保存順を使う。

`format=detail-page`は既存の管理者限定APIを使用する。年度・集計元・分母・入力リビジョン・集計日時を保存済み集計と照合し、途中で更新された場合は409で再集計を案内する。レスポンスの`private, no-store`、DBの管理者専用RLSを維持する。

既存のCSV全件出力と`include_details=1`は全明細を返す契約を維持する。DBのスキーマ変更は不要。保存形式には正確な明細総数`detail_count`を加え、計算版を3に更新する。既存の版2は原本のまま残り、条件ごとに初回アクセスで新版の集計キャッシュを生成する。集計ルール自体は変えない。

## 計測

Edge・Next.js本番ビルド・PGliteの同一フィクスチャ（201回答／1,206明細）で比較。キャッシュ生成後、PostgREST通信ごとに100msの遅延を追加し、背景先読みを除外した。

| 指標 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 初期HTML（非圧縮） | 405,683 bytes | 33,770 bytes |
| 集計概要の表示確認まで | 625ms | 570ms |
| 初期表示時の明細API呼び出し | 0回（全明細をHTMLに含む） | 0回（明細はHTMLに含めない） |

初期HTMLは約92%削減。時間は各1回のローカル計測で、本番速度の保証や安定した短縮率を示すものではない。既存の107作品・投票なしの初期通信計測も8回以内を維持した。
