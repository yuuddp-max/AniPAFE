# 過去投票者の紐付け

運営管理の「過去投票者の紐付け」で、登録済みの任意年度の過去フォーム回答と `data_login_user` を回答単位で対応付けます。

1. 「紐付け年度」を選び、原本の名前・ニコニコID・回答行で回答を探します。
2. 「紐付けを編集」を開き、ログインユーザーを検索・選択します。ID一致候補を先に表示しますが、自動選択・自動確定はしません。
3. 保存先の名前・ニコニコID・ユーザーIDを確認し、「確認内容・変更理由」を入力して保存します。
4. 同じ画面で紐付け先の変更・解除ができます。操作履歴に操作者・年度・変更前後のユーザーID・理由を記録します。

紐付けは `data_historical_voter_links` に保存し、同じトランザクションで `data_ballot.voter_id` にも同期します。変更時は新しいユーザーID、解除時はNULLを反映します。原本の名前・ニコニコID・回答JSON・投票明細、サイトの投票所有者、集計ルールは保持します。紐付け先ユーザーのプロフィール変更で原本のニコニコIDを書き換えることもありません。複数回答が同じ人に対応する場合も、元の回答を統合せず個別に紐付けられます。同期時に回答の更新番号を進め、古い画面での削除を防ぎ、保存済み集計は次回読込時に再計算します。

## 本人の投票画面への表示

本人の投票画面は、サイトの選択が未入力・未確定の場合に紐付け済み原本を既定表示します。6部門の件数、選択作品と感想を原本どおりに表示し、サイト投票としてコピー・再確定しません。原本は閲覧専用です。「表示する投票」でサイト投票や複数の原本を切り替えられます。サイトに保存済みの選択・確定票がある場合はそちらを優先し、切替前に未保存のサイト変更を保存します。

部門別の画面は通常の投票と同じ全作品のカード一覧です。PCでは3列・1ページ12作品を表示し、原本の選択作品を緑枠で示します。検索・絞り込み・並び替え・ページ切替・再生を利用でき、右側の選択一覧で原本の感想を確認できます。原本の選択・感想の変更はできません。作品マスターにない回答も選択一覧に残し、感想のみの回答は作品数に加えません。確認画面では全6部門の原本明細をまとめて表示します。

`linked_original_votes` RPCはGoogleログイン本人のUUIDと、対応表および回答のユーザーIDが一致する対象年度の原本だけを返します。管理者でもこのRPCで他人の原本は取得できません。テーブルのRLSは変更せず、回答JSON・投票者名・元のニコニコIDは返しません。解除・変更後は旧本人に返さなくなります。選択重複は枠ごとに保持し、作品マスターにない選択は原本ラベルで表示、作品未選択の感想は件数に含めず別明細として表示します。

移行ファイル：`supabase/migrations/20261016132510_linked_original_vote_view.sql`。

同期用の追加移行は `supabase/migrations/20261016130827_sync_historical_ballot_voter.sql` です。既存の紐付け済み回答にも反映します。ユーザー・年度の一意制約はサイト投票だけに適用し、同じ年度の原本回答とサイト投票を共存可能にします。サイト投票の取得・保存・確定・プロフィールと本人履歴は `source=site` に限定します。

管理者だけが参照・操作できます。更新は管理者確認付きRPCを通し、直接のINSERT/UPDATE/DELETEは管理者のブラウザーからも禁止します。年度と原本種別をDBでも確認し、更新番号と原本行ロックで同時編集を検出します。解除後も更新番号を保持するため、古い画面で上書きできません。一覧はDBの取得上限を超えてページングし、画面には50回答ずつ表示します。原本回答JSON・感想・メールアドレスはこのAPIに含めません。

DB移行: `supabase/migrations/20261016122639_historical_voter_links.sql`。アプリを公開する際は先にこの移行を適用します。移行は対応表とRPCのみを追加し、既存回答に自動で紐付けを作りません。
