# ヘッダーの画面切り替え改善（2026-10-29）

## 変更

- `/history` に読み込み境界を追加。共通の `src/app/loading.tsx` で、データ取得がある `/vote/layout.tsx` も外側から覆う。Next.jsの通常の部分先読みを使い、取得完了を待たず画面を切り替えられるようにする。
- 共通ヘッダーのユーザー情報・対象年度を並列取得する。投票データの取得では、認証確認と年度設定の読み込みを並列で開始する。
- 未保存の下書きがある場合も、保存成功後に `router.push()` で移動する。従来の `window.location.assign()` によるページ全体の再読み込みをなくす。
- 投票内容のフル先読み・長時間キャッシュは追加しない。別画面にいる間に更新された投票も、戻ったときに取得する。

DBスキーマ、RLS、認証・管理者判定、下書き保存APIの変更はない。

## 確認

Edge・Next.js本番用ビルド・ループバックのPGliteテストDBで、各PostgREST通信に300msの遅延を加えて計測した。集計キャッシュは事前に生成し、画面切り替えの比較に初回集計の負荷を含めない。

投票画面へ戻るクリックからヘッダーの選択状態が切り替わることを確認するまでの時間は、変更前1,936ms、変更後49〜59ms。操作への反応を改善するもので、すべてのデータ取得がこの時間で終わるという意味ではない。実際の作品表示確認までは同じ遅延条件で約2秒かかる。本番サイトの実測値ではない。

作業ツリーでは以下の8件が成功した。今回の配信対象に含まれるE2Eは画面切り替え・管理画面の3件で、配信用ソースだけを切り出した環境でも再確認する。

- ヘッダー3リンクの遷移、未保存コメントの保存後に文書全体を再読み込みせず移動、再訪時の保存内容・外部更新の反映。
- 管理画面の初期通信8回以内、未表示一覧の遅延取得、選択年度保持、取得失敗後の再試行、匿名401・一般ユーザー403。
- 登録済み・未登録それぞれのURLアクセスとGoogle認証後の遷移、匿名アクセス・認証失敗時のログイン画面表示。

管理画面の初期通信計測は、ブラウザーの背景先読みを除外してページ自体の通信を数える。本番用ビルドでも開発モードと同じ条件で比較できるようにした。

再現手順（ビルドとE2Eは順番に実行する）:
