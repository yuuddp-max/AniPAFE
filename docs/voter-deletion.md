# 投票者・修正の削除操作

選択年度の各行に「削除」を表示する。サイトの下書き・確定済み投票と、過去フォーム原本の回答を対象とする。

削除理由を入力し、年度・表示名・ニコニコID・削除範囲を確認して実行する。キャンセルした場合は送信しない。削除するのは、その行の投票回答と関連する投票明細・感想のみ。別年度の投票・プロフィール・ログイン用アカウントは保持する。アカウント自体を停止する操作ではないため、受付期間中のサイト利用者は改めて投票できる。

運営者の権限はAPIとDB関数の両方で確認する。年度と投票回答IDで対象を限定し、読み込み時の更新番号が一致しない場合は409相当の競合として拒否する。削除理由・操作者・年度・元状態・集計元・削除明細数を既存の運営専用監査ログに記録する。既存トリガーで集計キャッシュを無効にする。

DB関数は `supabase/migrations/20261016103612_admin_year_delete_ballot.sql`。公開関数はSECURITY INVOKER、権限を持つ実装はprivateスキーマに置き、既存の運営認可関数を必ず通す。テーブルへの直接削除権限やRLSは変更しない。

本番反映時は、このマイグレーションを先に適用してからアプリをデプロイする。マイグレーション適用だけでは既存の投票データは削除されない。
