# Excel方式の集計

集計は **DBの投票明細 → 部門別の票数 → 補助合計・同点順位 → 部門別スコア・合計スコア** の順に、プログラム内で毎回計算します。管理画面はExcelファイルやExcelの計算済みセルを読みません。投票明細が変われば、その明細から結果を再計算します。

運営管理の集計画面は **「集計・明細」** タブに統合しています。運営管理を開くと、このタブに上部の対象年度の結果と投票明細を自動表示します。集計元の既定は「集計年度のデータから自動選択」で、その年度に取込済みの過去フォーム回答がある場合は原本を、ない場合はサイト確定票を表示します。部門順位とスコア計算を切り替えて表示し、それぞれCSVで保存できます。年度・集計元・スコア分母を変更した場合は「Excel方式で集計」を実行します。**上部の対象年度に関係なく、登録済みの任意の集計年度を選べます。** 集計年度を選んでもイベントの対象年度は切り替わりません。集計年度を変更すると集計元は自動選択に戻ります。必要に応じて原本・サイト確定票を明示指定することもできます。

ダッシュボードには、選択した集計元の総投票数・投票回答数・得票作品数・集計部門数と、順位表・スコア表・投票明細を表示します。順位表の部門選択で6部門を切り替えられます。順位は補助合計も使った計算結果を表示します。

詳細では作品名・製作者名・作品番号で検索できます。PCは順位表、スマートフォンは作品と票数を並べたカード形式です。「補助合計・加点の詳細」を選ぶと絶対順位・製作者加点・補助合計も確認できます。スコア表は合計スコアの降順です。検索は表示だけを絞り込み、CSVには選択年度・集計元の全作品を出力します。年度全体の登録状況は上部で開閉できます。

**集計結果と投票明細を同じ画面で表示**し、選択した集計元の投票者・感想・明細を50件ずつ閲覧できます。明細CSVは全件を出力します。部門順位とスコア計算を切り替えても投票明細は表示され、明細のページ位置を保持します。上部は対象年度の登録状況として「サイト下書き」「サイト確定投票者」「過去フォーム回答」「過去フォーム票数」を区別します。

## 対象と加点

- 「過去フォーム原本（暫定）」は `data_ballot.source=historical / status=imported` と対応明細を使用します。
- 「サイトの確定済み投票」は `source=site / status=submitted` と対応明細を使用します。下書き・別年度・別集計元を混ぜません。
- 過去フォームは保存原本の比較用集計です。公開結果への採用や投票の確定、本人との紐付けは行いません。
- 製作者が投票した作品の総合賞への加点は、作品ごとに **0または1ポイント**。現在の画面では確認資料がないため未加算・暫定として扱い、総合賞に「票数～票数+1」の範囲を表示します。加点を推測したり、全作品に一律加点したりしません。
- 1ポイント差は同点時の補助合計・順位・スコアにも影響します。順位やスコアの差を1以内に抑えるという意味ではありません。
- 作品マスターにない作品への票は、原本の作品番号・作品ラベルで集計します。感想だけの明細は票に数えません。原本の重複選択は票としてそのまま数えます。
- DBからの取得は1,000行ごとにページングし、全明細を読みます。
- 集計APIの通常JSONに個人の明細は含めません。管理者の明示的な明細要求（`include_details=1` または `format=details`）と認可済み運営管理画面だけに表示します。原本回答の全JSONをクライアントへ送信しません。
- 集計APIは集計元省略時または `source=auto` の場合、指定年度の原本の有無で集計元を選びます。画面のCSVリンクは表示結果の年度・集計元を指定します。既存の `/api/admin/export` も同じ計算処理を使い、上部の対象年度に関係なく指定年度を出力できます。両APIとも未登録年度は404で拒否し、認証・管理者権限を必須とします。

## Excelから確認した計算

| 項目                   | 計算方法                                                                             |
| ---------------------- | ------------------------------------------------------------------------------------ |
| 部門得点               | その部門の選択数。総合賞だけ確認済みの製作者加点を追加                               |
| 補助合計（テーマ以外） | 総合＋選曲＋構成＋諧謔＋クリエイティブ。テーマは含めない                             |
| 補助合計（テーマ）     | テーマ＋選曲＋構成＋諧謔＋クリエイティブ。総合は含めない                             |
| 順位（絶対）           | 部門得点の降順。同点は同順位、次は1だけ増える（1、1、2）                             |
| 順位（相対）           | 部門得点→補助合計の降順。両方が同じなら同順位（1、1、2）。表示順だけ作品番号で安定化 |
| 0点作品                | 部門順位の対象外。確認済み加点が1なら総合賞の対象                                    |
| スコア                 | `(1 - 相対順位 / 分母) * 100`。既定の分母はサンプル式の **143**                      |
| スコア対象             | 総合70位・テーマ10位・他4部門15位以内。それ以外は0                                   |
| 受賞数                 | 上記対象のうち総合を除く5部門の数                                                    |
| 合計スコア             | 6部門のスコア合計。途中で丸めず、画面だけ小数3桁表示                                 |

サンプル `02_AniPAFE2025投票フォーム_サンプル.xlsx` の `6総合賞!K:L / 5選曲賞!K:L / 4構成賞!K:L / 3諧謔賞!K:L / 2クリエイティブ賞!K:L / 1テーマ!M:N`、および各部門の絶対・相対順位列、`スコア計算!D:Q` を確認しました。

サンプルには `動画データ` への参照切れ、総合順位の `#REF!`、一部手入力された相対順位、旧年度の作品名を残したスコア表があります。これらの値を転記せず、上記の計算方法に沿って現在の作品と票から再計算します。スコア表の一部の旧部門見出しも、そのセルが参照する実際の部門名に合わせています。そのため、サンプル内の不整合や未確認加点に由来する順位・スコアをそのまま再現するものではありません。

## ローカルプログラム

同じ計算をオフラインで実行できます。入力は既存の過去フォーム変換JSON（`ballots` / `entries`）と、その年度の作品マスターJSONです。投票者の表示名・ID・感想・元回答は出力しません。

```powershell
npm run tally -- --year 2025 --votes artifacts/vote-import-2025/converted.json --videos artifacts/vote-import-2025/videos.json --out artifacts/tally-2025
```

出力は `ranking.csv`（部門順位・得点・補助合計・加点確認状態・放送情報）、`score.csv`（部門順位・部門別スコア・受賞数・合計）、`result.json`（全結果・計算条件・注意）、参照指定時の `comparison.json`（得点照合）です。CSVはUTF-8 BOM付きで、作品名・製作者名の数式注入を防ぎます。

`--reference` は省略できます。指定時は同年度のExcelにある時間・合作・放送対象の入力値を作品ID照合後に読み、サンプルの部門得点と比較します。**部門得点や製作者加点をExcelから集計結果へコピーしません。** Excelの数式・マクロ・ハイパーリンクは実行しません。

放送対象はサンプルで手入力されている値です。参照なしの管理画面では「未設定」とし、順位から推定しません。参照を指定したローカル実行では、総合→選曲→構成→諧謔→クリエイティブ→テーマの順に、既に放送対象となっている作品の再掲を60秒に短縮します。各部門の相対1位は全編、総合は全編です。未入力の動画時間は不明のままにします。

製作者加点の確認資料が得られたら、作品番号をキーとするJSON（例：`{"33":1,"13":0}`）を作り、`--bonus path/to/confirmed-bonus.json` を指定できます。**0は確認済みの加点なし、キーの省略は未確認** です。1は作品ごとに一度だけ総合へ加えます。これはローカル計算用で、DBへ保存しません。スコア分母の変更は `--denominator` です。

## 検証記録（2026-10-15）

- 実データ：90回答・2,013明細（2,008票・選択なしの感想5明細）。削除済みNo.17・72・88の票も集計。
- Excelを指定しない実行でも90回答・2,008票を集計。投票追加による得点・同点時の補助合計・順位・スコアの変化と、同じ入力での再計算一致を回帰テストで確認。
- サンプルの部門得点389件を全件照合。302件完全一致、87件は総合賞の未確認加点による1ポイント差。その他の差分0、サンプルにない得票作品0。総合以外の275件は全件一致。
- 得点・同点処理・テーマの補助合計・加点0/1/未確認・スコア境界・放送短縮・不正入力・CSV式注入を単体テスト。
- PostgreSQL（PGlite）の実テーブル/RLSを使うE2Eで、認証/管理者権限、1,206明細の全件取得、年度・原本/サイト票の分離、CSV、PC/390px画面を検証。
- 運営管理を開くと統合後の「集計・明細」が選択され、初期HTMLに順位と得点を含むことを確認。集計ボタンを押さずに集計結果・明細・明細CSVを表示し、「集計結果」タブが残っていないことを回帰テスト。
- 2025年度の「集計・明細」で、過去回答・票数のカード、明細の50件表示、スコア表示切替後の明細ページ保持、旧・新CSV経路の一致、一般ユーザーの明細拒否を確認。
- 対象年度2026のまま2025年度の原本1,206票を集計し、明細と新旧CSVを取得できることをE2Eで確認。集計年度を2026へ戻すと同年度のサイト確定票10票に自動選択され、再読み込み後も対象年度は2026のまま。対象年度2025へ切替後も2026年度を集計でき、未登録年度は404・一般ユーザーは403で拒否。集計E2E 2件、単体・DBテスト34件、型チェック、本番用ビルドが成功。

公開はGitHubの `main` への反映とVercelの本番デプロイで行います。集計が依存するDB移行は本番適用済みのため、この機能のデプロイに伴う新たなDB更新は不要です。
