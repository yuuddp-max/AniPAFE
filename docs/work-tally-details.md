# 作品別の得票・感想

運営管理の部門順位表・スコア表・スマホ順位一覧で作品名を押すと、作品詳細ダイアログを開く。

- 6部門の相対順位・投票分・投稿者参加分・得票、スコアを同じ集計結果から表示。
- 未確認の投稿者参加分は「未確認」と表示し、0と区別する。得票0の部門は順位を「—」とする。
- 作品別明細・感想を必要時に50件ずつ取得。既存のキーワード・部門・感想ありの検索を組み合わせられる。条件クリアも当該作品の範囲にとどまる。
- 閉じるボタン・Escapeで閉じ、元の一覧へ戻る。集計条件変更・再集計後には古い作品詳細を表示しない。
- 管理者専用。作品番号で特定するため、同じ作品名や動画IDのない原本作品を混同しない。

保存集計の明細に`work_number`を追加し、計算版を4に更新する。既存版3の保存結果は保持され、条件ごとの初回集計時に版4を生成する。集計ルール・CSV出力列は維持する。初回のみ再計算の待ち時間が発生する。

新RPC`admin_work_tally_details`はSECURITY INVOKER。既存の管理者確認と集計テーブルのRLSを使用し、年度・集計元・分母・計算版・日時・入力リビジョンを照合する。古い集計の要求はAPIで409を返す。

本番反映は `20261029122514_work_tally_details.sql` を適用してからアプリをデプロイする。DB関数は本番に適用済み（クラウドのマイグレーション番号と同期）。

## 検証

- 独立した検証ディレクトリで本番ビルド・型チェック成功。
- DB単体テスト3件成功。同名・動画IDなしの2作品を区別し、ページ分割・権限・更新後の古い集計の拒否を確認。
- 関連E2E5件成功。PC順位表・スコア表・幅375pxのスマホ一覧からの開閉、6部門、50件ずつの明細、Escape、元の作品へのフォーカス復帰を確認。既存の検索・CSV・年度切り替え・初期取得も検証。
- 初期表示は作品詳細APIを呼ばず、合成データ1,206明細の初期HTMLは33,755 bytes。作品詳細のコードは動的に読み込む。
