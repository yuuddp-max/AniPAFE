# 複数年度対応

## データ構造

- `master_poll_settings` に年度（unique）と投票画面タイトルを追加。既存のid=1は2026年度として維持。
- `master_event_settings` の1行で対象年度を管理。変更は運営者RPCのみ。
- `data_mad` は `(year, video_id)`、`data_ballot` は `(voter_id, year)` で年度を分離。
- `data_ballots` は年度付き外部キーで、作品・投票が必ず同じ年度に属することをDBで強制。
- 既存行に2026年度を追加。移行トランザクション内で作品・投票・明細・設定・監査の全既存フィールドのチェックサムを照合し、変化があればロールバック。
- プロフィール・運営者は共通。過去フォーム原本は保持し、年度別管理の修正対象に含めない。
- 投票設定は上部の対象年度を操作する。集計・明細・CSVに加え、「作品マスター」「投票者・修正」は各タブで登録済み年度を独立して選択できる。作品編集・CSV/XLSX取り込み・サムネイル更新・投票再開は選択年度だけに反映し、公開中の対象年度は変えない。
- ニコニコIDは全年度共通。運営によるID訂正は、全年度のサイト確定票を先に再開してから行う。全年度の下書きから新たに自薦となる選択を削除し、revisionを進める。過去フォーム原本は閲覧のみで、ID訂正・再開では変更しない。

## 過去投票一覧のデザイン案

既存の緑・生成り色・角丸のデザインに合わせ、年度カードをPCで3列、スマホで1列表示します。

1. 年度カードに大きな年・年度別タイトル・「投票済み／下書きあり・未確定／投票記録なし」・結果公開状況・確定日時を表示。
2. 年度を選ぶと同じページ内に詳細を表示。URLの `?year=2026` で直接開けます。
3. 「自分の投票」は部門別に作品名・投稿者・自分の感想を表示。確定と下書きを明確に区別し、閲覧専用にします。
4. 「投票結果」は部門選択と順位・作品・投稿者・票数の一覧。同得票は同順位。上位の順位を淡い金色で表示。
5. 年度未登録・未投票・保存作品なし・結果未公開それぞれに説明を表示。未来の準備年度は過去一覧に出しません。

「投票画面へ」の右隣に「過去投票データ」を置き、投票画面の見出しの下にも本人の過去票へのリンクを置きます。履歴はGoogleログイン必須です。本人の明細と、運営が公開した確定票の集計だけを返し、他人の投票内容・感想・IDは返しません。

## 運用

1. 運営画面上部「新しい年度を追加」で年とタイトルを入力。
2. 「対象年度」を選び「対象年度を切り替え」。投票・管理の対象が切り替わります。
3. 「作品マスター年度」で管理したい年度を選びCSV/XLSXを取り込む。対象年度へ切り替える前の新年度準備もできる。「年度・投票設定」で対象年度のタイトル・日本時間の期間・受付を設定。
4. 終了後に結果を公開する場合は、その年度を対象にして結果公開を保存。
5. 新年度へ切り替えると前年度を過去投票データで閲覧できます。

年度切替時に当該年度の下書きrevisionとマスターrevisionを進めます。古い画面の年度はRPCで照合し、別年度への誤保存は409で拒否します。旧引数だけのDB呼出は2026年度限定です。新年度の下書きは初回保存で自動作成します。

年度別の管理画面は `admin_year_import / admin_year_reopen / admin_year_thumbnail / admin_year_profile` を使い、年度を明示指定します。管理者確認・年度の存在確認・操作履歴の年度指定をDBで行います。旧RPCと一般投票の対象年度チェックは維持します。作品変更では選択年度のmaster_revisionと確定票の整合性を検証し、別年度の作品や票は変更しません。取り込み確認トークンも年度・作品内容・master_revisionに紐付きます。

「投票者・修正」は選択年度に投票データがある方だけを表示します。サイト投票は下書き・確定済みを区別し、過去フォームは取込済みの閲覧専用原本として表示します。年度の読み込みに失敗した場合は古い一覧を隠し、再読み込みを表示します。各タブの選択年度はタブ間の移動でも保持します。

管理タブはPCで等幅の5列、980px以下では「年度・投票設定」を先頭の全幅、その下を2列にします。タブ名と機能の短い説明を常に表示し、PCではアイコンを併記します。選択中は濃い緑と白文字で区別し、キーボードのフォーカスは外枠で示します。横スクロールを使わず全タブを表示し、各ボタンは44px以上の高さを確保します。タブ移動では集計年度・検索・部門・明細ページも保持し、編集後のサーバー更新時は選択条件のまま集計を再取得します。

本番DBには `20261015123601_independent_admin_years.sql` を適用済みです。この移行は関数追加のみで、既存データ・テーブル・RLSポリシーを変更しません。アプリはGitHubのmainへの反映による既存のVercel連携で公開します。
