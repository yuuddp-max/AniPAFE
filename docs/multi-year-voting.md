# 複数年度対応

## データ構造

- `master_poll_settings` に年度（unique）と投票画面タイトルを追加。既存のid=1は2026年度として維持。
- `master_event_settings` の1行で対象年度を管理。変更は運営者RPCのみ。
- `data_mad` は `(year, video_id)`、`data_ballot` は `(voter_id, year)` で年度を分離。
- `data_ballots` は年度付き外部キーで、作品・投票が必ず同じ年度に属することをDBで強制。
- 既存行に2026年度を追加。移行トランザクション内で作品・投票・明細・設定・監査の全既存フィールドのチェックサムを照合し、変化があればロールバック。
- プロフィール・運営者・6部門の定義は共通。過去票の再検証や変更は行わない。
- 年度別の作品取り込み・設定・再開・サムネイル更新・プロフィール訂正・CSVは対象年度に限定。プロフィールのニコニコIDロック判定も対象年度のみ。

## 過去投票一覧のデザイン案

既存の緑・生成り色・角丸のデザインに合わせ、年度カードをPCで3列、スマホで1列表示します。

1. 年度カードに大きな年・年度別タイトル・「投票済み／下書きあり・未確定／投票記録なし」・結果公開状況・確定日時を表示。
2. 年度を選ぶと同じページ内に詳細を表示。URLの `?year=2026` で直接開けます。
3. 「自分の投票」は部門別に作品名・投稿者・自分の感想を表示。確定と下書きを明確に区別し、閲覧専用にします。
4. 「投票結果」は部門選択と順位・作品・投稿者・票数の一覧。同得票は同順位。上位の順位を淡い金色で表示。
5. 年度未登録・未投票・保存作品なし・結果未公開それぞれに説明を表示。未来の準備年度は過去一覧に出しません。

「投票画面へ」の右隣に「過去投票データ」を置き、投票画面の見出しの下にも本人の過去票へのリンクを置きます。履歴はGoogleログイン必須です。本人の明細と、運営が公開した確定票の集計だけを返し、他人の投票内容・感想・IDは返しません。

## 運用

1. 運営画面上部「新しい年度を追加」で年とタイトルを入力。
2. 「対象年度」を選び「対象年度を切り替え」。投票・管理の対象が切り替わります。
3. 作品マスターを取り込み、「年度・投票設定」でタイトル・日本時間の期間・受付を設定。
4. 終了後に結果を公開する場合は、その年度を対象にして結果公開を保存。
5. 新年度へ切り替えると前年度を過去投票データで閲覧できます。

年度切替時に当該年度の下書きrevisionとマスターrevisionを進めます。古い画面の年度はRPCで照合し、別年度への誤保存は409で拒否します。旧引数だけのDB呼出は2026年度限定です。新年度の下書きは初回保存で自動作成します。

## 検証

- `tests/years.test.ts`：既存の確定票を含む移行、同じ利用者・作品IDの年度分離、古い年度の保存拒否、本人限定の履歴、未公開・公開結果、匿名・Google以外・一般ユーザーの管理拒否、年度をまたぐ外部キー、タイトルと終了前公開の制約。
- `tests/e2e/voting.spec.ts`：年度追加と切替、タイトルとブラウザータブへの反映、前年度の作品が現年度へ混入しないこと、本人の過去票・他人の未投票表示、未公開と公開結果、スマホ幅、テキストとしての感想表示。
- ローカル検証は実PostgreSQL（PGlite）とNext.jsを使用。認証/PostgREST通信はテスト専用ハーネスを使用し、Google実認証とは区別します。

本番の年度追加・切替・結果公開は、この実装作業では行いません。対象年度2026と既存の受付・公開設定を保持します。アプリの公開はデプロイ後に反映されます。
